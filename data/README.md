# 数据采集与档案规范

网站方案要求文物档案、来源证据、学术解释和媒体授权分别管理。`artifact.schema.json` 是后续主档案的 JSON Schema；`sources.json` 是可访问来源清单；`acquisition/` 保存每次采集的原始 HTML 和采集记录。原始网页不等于已核实的文物档案，必须逐字段关联来源并经过人工审核后，才能进入公开目录。

## 百件以上图录器物档案（当前百科数据集）

- `artifacts/selected-book-300.jsonl`：当前文物百科的300条记录，来自用户提供的四川省文物考古研究院等编《三星堆出土文物全记录》（天地出版社，2009）三册。清单按青铜器120条、陶器/金器90条、玉器/石器90条编排；这是网站首批精选方案，不是官方重要性排名。
- `artifacts/pit-report-finds.jsonl`：来自本项目提供的K3、K4、K5、K7、K8专项简报 PDF 的独立器物档案；不属于精选300件，不参与百科列表，也不从 `acquisition/` 合并补齐。当前整理11条有报告编号的记录：K3 3条、K4 3条、K5 1条、K7 2条、K8 2条；K6没有专项PDF或该数据集中的记录。个别条目是复合器/组合档案，按报告粒度保留。
- `artifacts/images/pit-report-finds/`：对应简报页截图，保留报告图版及页码上下文。`media.image_kind`、`alt`、`attribution` 和 `source_url` 记录截图性质与出处；图片文件是出版物页面截图，报告未说明开放许可时使用 `rights_status: permission_required`、`license: 授权待核`。这些截图不能被描述成获得授权的独立馆藏照片。
- 专项简报档案依照 `artifact.schema.json`；`media.alt`、`media.image_kind`、`media.source_url` 为可选扩展字段。所有记录在人工复核前保持 `record_status: needs_review`。坑位探索从静态 manifest 同时读取精选图录与专项简报档案，并在界面区分数据集来源。
- 每条包含器名、图录编号、书内出土编号、类别、材质、尺寸、遗址/可识别坑位、简介、卷名和精确页码定位。简介从逐件图注 OCR 清理，尽可能保留器形、部件、纹饰和保存状况描述；OCR 未识别到描述时明确提示核读原页，不根据器名推断。
- `artifacts/images/book-2009-NNN.jpg`：按300条档案逐条生成的图录页截图。单件图版已裁去页边和大部分图注；少量同页上下排版按版面分条裁切；45条位于密集图版的记录保留整页截图，并在索引与图片说明中标出同页还有其他器物。`artifacts/image-index.csv` 记录每图的档案ID、名称、卷、页码和裁切类型。
- 截图路径已写入每条记录的 `media` 数组，网站文物百科直接展示。图片来自本机扫描PDF，页面许可/使用范围尚未单独核实，媒体字段保留 `rights_status: unknown`；书内页码和扫描 PDF 页序作为来源定位。
- 来源记录的定位包含书内页码和扫描 PDF 页序。所用扫描件保存在项目上级目录 `文物全记录300件提取/`，网站数据只提供书目信息及页码，不公开镜像 PDF。
- 300条均为 `needs_review`。书名、页码和筛选名单来自原始目录，器物字段与简介仍需逐页对照扫描图人工校验；未能从图录确认的年代、收藏单位和额外解释保持空值。
- 网站百科只读取该300条主数据集，不再叠加此前100条采集档案、4条陶器器型资料和首页精选档案；旧档案继续保留在各自目录用于来源追溯。
- 使用 `py scripts/import_book_300_artifacts.py` 从上级 OCR 提取目录重建主数据，再使用 `py scripts/build_web_data_bundle.py` 同步到 `dist/data/`。
- 使用 `py scripts/extract_book_300_images.py` 重新从三册 PDF 渲染截图并更新 JSONL 媒体路径；随后运行数据镜像脚本。

## 考古背景档案

`archaeology/` 保存遗址、祭祀坑等考古单位、考古事件时间线和发掘报告目录：

- `sites.jsonl`：三星堆遗址整体档案；不把祭祀区或八座祭祀坑当作遗址全貌。
- `contexts.jsonl`：K1—K8逐坑档案，记录已知发现与田野发掘日期、位置、尺寸、层位关系、坑群年代证据和报告关联。空值表示已查来源尚未支持该字段，不表示事实不存在。
- `events.jsonl`：遗址发现、早期发掘、K1/K2发现以及K3—K8新一轮发现与发掘项目时间线。
- `reports.jsonl`：公开发掘简报与考古报告的题录、覆盖坑位、全文状态和访问链接。
- `schema.json`：上述四类 JSONL 记录的结构定义。每行是一个独立 JSON 对象；来源中的 `supports` 指明该来源支持的字段。

报告统计保留原报告口径与阶段属性。K1、K2目前只落实到1986年年度；K5、K6逐坑发现日和起止工期在当前公开来源中未核实，不以2019—2022项目总周期代替。K3、K4、K6、K8的公元前1201—前1012年区间来自2025年论坛成果的政府报道转述；K7的同一范围属于跨坑拼接关系支持的坑群推断，不是直接测年。K3、K8档案同时保留2024年简报较窄的测年区间，供研究者追溯版本。2025年报道不是原始测年论文，取得正式论文后应补充并优先关联原始数据。

本目录是按已访问公开来源整理的研究型起始档案，不宣称穷尽全部考古记录；记录目前均为 `needs_review`。引用 PDF 的原文页码、K1简报作者署名、个别报告作者和K5/K6专项报告仍需人工逐页核验。网页展示时应同时显示报告版本和来源链接，不把推断年代写成无条件确定事实。

## 时间线与器物关系图谱

`graph/` 将300件精选图录器物、遗址、坑位、事件和专题展览整理为可查询关系：

- `nodes.jsonl`：实体索引；文物节点只来自 `artifacts/selected-book-300.jsonl`，并关联考古档案、图录中的材质/工艺原词及专题展览节点。
- `edges.jsonl`：每条关系都带来源 URL、定位和所支持字段；当前覆盖300件图录记录中的遗址/坑位、材质/工艺标签，以及事件覆盖坑位等考古关系。空缺坑位不推断；图录未提供的年代关系不生成。
- `exhibitions.jsonl`：上海博物馆“星耀中国：三星堆·金沙古蜀文明展”和香港故宫文化博物馆“凝视三星堆——四川考古新发现”的展期、场馆、展品规模及出处。
- `schema.json`：图谱节点、关系边与证据结构。
- `scripts/build_relationship_graph.py`：以 `artifacts/selected-book-300.jsonl` 为唯一文物节点来源，并从 `archaeology/` 生成考古背景关系；旧 `acquisition/` 记录不会混入图谱。展览保留为独立节点，只有300件图录记录及其来源能逐件支持时才建立器物—展览关系。运行：`py scripts/build_relationship_graph.py`。

展览节点记录机构公开的展期、场馆和展品规模；没有300件图录中的单件展览证据时，不生成器物—展览关系。坑位关系保留图录来源原始标签，并仅对明确的“一号祭祀坑”“二号祭祀坑”等标签映射到K1—K8考古档案；其余标签作为未解析上下文保存。图录中的材质/工艺混合标签按原词保留，不擅自拆分为确定材料和制作方法。所有新生成的文物关系继续标记为 `needs_review`。

## 研究问答知识条目

`qa/` 保存可用于研究型问答检索的短答案单元，不保存考古报告全文：

- `knowledge.jsonl`：当前首批 17 条问题—答案记录，覆盖K3、K7、K8发掘事实与阶段统计、年代口径、坑间关系、埋藏行为解释及跨坑拼对。每条答案按来源改写，包含精确到印刷页/段落的定位、关联坑位和器物档案 ID、证据类型及回答限制。
- `schema.json`：问答记录字段定义。`answer_kind` 区分报告事实、研究推断、解释和资料限制；`caveats` 提醒检索系统保留不确定性、统计口径与版本差异。
- 2024年K3简报、2024年K8简报和2025年K7简报已用印刷页码加 PDF 页码定位。2023年跨坑拼对记录使用四川省文物考古研究院报道的具体段落定位。摘要中的“件（组）”、阶段性统计和概率年代按来源原口径保留。
- K3旧简报区间与2025年论坛报道的更新区间并列保存。后者目前只有政府新闻转述，尚待补充联合测年正式论文和原始样本/校正信息；K7简报发表时明确称该坑碳十四测年尚未完成。系统不得把这些不同状态的年代压成单一答案。
- 所有新条目初始状态为 `needs_review`。正式接入AI问答前，应人工复核页码、相关档案匹配和统计口径；回答应返回证据链接及页码，不能以书目标题代替正文证据。

## 图片与媒体授权台账

`media/` 逐文件登记可发现的图片、视频、音频和三维模型授权信息：

- `assets.jsonl`：每个文件一行，记录原始文件页、文件链接、作者/上传者、来源、许可条款、署名文本、技术规格，以及与器物档案的匹配和使用审核状态。
- `schema.json`：媒体记录字段定义。许可状态与器物身份匹配状态分开维护；获得图片许可不等于确认图片拍摄的就是某个具体馆藏编号。
- `artifact-photo-coverage.jsonl`：为100条器物档案逐条列出图片覆盖状态、关联媒体 ID、匹配级别和用户要求展示的图片数量。不得把类别图、组合图或发掘现场图标成器物单件照。
- `coverage.json`：汇总媒体条数、权利状态和器物照片覆盖状态。
- 截至2026-10-18共有105条图片记录：80条Wikimedia Commons开放许可照片记录（其中2条为新闻视频截图，不是独立视频资产），以及25条四川省文物考古研究院、香港故宫展品页、四川在线和展览/发掘页面照片。25条待确认记录虽带有 `display_override: user_requested_display`，该标记仅代表曾提出展示指令，不改变权利状态；当前 `dist/app.js` 的 `usableMediaAsset` 会要求使用审核通过且权利状态为开放许可声明或已记录授权，因此这些待确认图片不会由器物图片选择器渲染。汇总目录中的媒体 CSV 已排除这25条；完整来源记录仍在 `assets.jsonl` 及其镜像中供追溯。
- 100条器物记录现均有关联图片：22条可核对为同件照片，78条关联类别参考、组合照片或坑位发掘现场图。后者须按图注标为“同类参考”“组合图”或“发掘现场”，不能称作具体器物的单件实物照。照片匹配数按档案统计，一张图可以关联多条档案。
- 新增器物照片记录可用 `py scripts/enrich_artifact_photo_register.py` 重建，再用 `py scripts/build_web_data_bundle.py` 同步到 `dist/data/`。该采集步骤只登记公开文件链接，不下载或镜像远程图像。
- 目前没有核验入库的独立视频、音频、博物馆高清母版或 3D 模型。此处表示本项目台账尚无已核验资源，不代表网上不存在相关资源。新增资源须分别记录文件授权凭证、权利人、许可范围（含商业使用、改编、下载/托管）、原始页面和器物对应依据；授权未落实时保持 `permission_pending` 或 `unknown`，不提供发布链接。

## 陶器器型档案

- `pottery/type-index.jsonl`：首批4条器型级记录，包括陶小平底罐、陶高柄豆、陶盉、陶鸟头把勺。它们用于填充陶器浏览入口，不等同于4件具备馆藏编号的单件藏品。
- 记录保留已知来源和未知字段：没有可核实依据的尺寸、坑位、层位、收藏单位和分期均留空或标为待核。青关山H105报告中的样本形态描述只适用于该报告样本，不外推到全遗址同类器物。
- 陶高柄豆与陶盉各有一张Commons类别配图，作者与CC BY-SA 4.0许可登记在 `media/assets.jsonl`；小平底罐和鸟头把勺暂用文字占位。类别配图不证明图中器物对应某一具体档案。
- 两份发掘报告的具体页码尚待逐页核对，故条目保持 `needs_review`。后续若取得单件目录，应拆分为逐件记录，并保留原有器型关联。

Commons 文件页标注的是上传者对该图像文件声明的许可。发布前仍需保留规定署名和许可链接，并核对文件页及其版本记录；不得把摄影作品许可描述成三星堆博物馆对文物高清图或三维数据的授权。视频截图仍受其图像文件页所列许可约束，不自动取得原视频的下载、剪辑或再发布权。

## 当前采集边界

三星堆博物馆藏品页面由 JavaScript 动态加载。官网前端公开脚本调用 `/san_official/v1/mainstay/list`，但该服务需要签名参数；匿名请求返回“签名参数异常”。采集器不会伪造签名、绕过服务校验或批量下载图片。应向博物馆申请正式数据导出、开放 API 或书面授权，再接入完整藏品清单。官网公开介绍称新馆陈列 1500 余件（套），这不意味着这些档案和影像都能通过公开网页批量复用。

本机脚本访问 `sckg.com` 和 `digicol.sckg.com` 时遇到 TLS 握手失败；文库目录和数字文物库条目通过内置网页读取采集。全文 PDF、图片和 3D 文件没有镜像或复制。文库目录可作为文献发现清单，数字文物库可作为结构化器物档案来源；仍需逐条打开原文、核验字段和授权后才能发布到网站。

## 运行

在项目目录执行：

```powershell
py scripts/crawl_public_sources.py
```

脚本只获取 `sources.json` 中明确列出的 HTTPS 页面，仅允许清单内的主机，默认两次请求至少间隔 2 秒，不跟随链接、不抓图片。遇到 SPA 页面时会在 `crawl_manifest.jsonl` 标记 `requires_render_or_authorized_export`，不会把空壳 HTML 当作文物数据。

## 记录原则

- 未知字段用 `null`，不要用推测值、示意图或模型生成文字补齐。
- 年代、出土位置、尺寸、编号等事实逐项记录来源 URL 与页面定位。
- 学术解释与可观察事实分开；不同解释分别记录状态、提出者和证据来源。
- 图片、视频、音频、三维模型记录权利人、许可和授权状态；未确认时不得镜像或发布。
- 原始快照保留 SHA-256 和采集时间，便于更新对比、纠错和追溯。
